## 2. PART B — OUTBOX & POSTGREST COMPATIBILITY VERIFIED

The durable local outbox and background synchronization pipeline have been verified against the PostgreSQL schema:

1. **Column & Payload Alignment:** All payloads generated by `queue_*` helpers match the PostgreSQL schema exactly:
   - `live_attack_events`: Uses `recommended_action` (not `mitigation_recommendation`), integer `acknowledged` (0/1), and string UUID v5 `event_uuid`.
   - `collector_status`: Integer `run_id` (BIGINT in Postgres) and integer counters.
   - `live_alerts`: Integer `window_id` (foreign key to `live_traffic_windows`), integer `run_id`, integer `acknowledged`.
   - `live_sensor_telemetry` & `live_pir_events`: Integer status flags (`dht_valid`, `motion_detected`), integer sequence and uptime numbers.
   - `unknown_device_obs`: Integer `run_id`, integer `observation_count`, integer `acknowledged`.
2. **Conflict Targets & Resolution Strategies:** Configured `TABLE_CONFLICT_CONFIG` in [`src/cloud_sync_worker.py`](file:///c:/Users/megha/OneDrive/Desktop/IoT_WiFi_Anomaly_Detection/src/cloud_sync_worker.py):
   - **Mutable State Tables:** `collector_status` (`on_conflict=run_id`), `device_registry` (`on_conflict=mac_address`), `unknown_device_obs` (`on_conflict=run_id,observed_mac`) send `Prefer: resolution=merge-duplicates`.
   - **Immutable Security Evidence Tables:** `live_traffic_windows`, `live_alerts`, `live_sensor_telemetry`, `live_pir_events`, `live_attack_events`, `station_pseudonym_map` send `Prefer: resolution=ignore-duplicates` with explicit `?on_conflict=...`. Because `UPDATE` is revoked from `collector_role`, `ignore-duplicates` prevents permission denied errors on duplicate delivery while guaranteeing idempotency.
3. **Idempotent Delivery After Network Interruption:** Simulated connection reset where server committed but response was dropped; subsequent retry handled gracefully (201/204 response reconciled to `DELIVERED`).
4. **Worker Non-Blocking Invariant:** Local packet processing performs solely local SQLite transactions (`commit=False` within collector loop). Network calls are handled entirely by an asynchronous daemon thread, ensuring the worker can never block packet capture or anomaly scoring.
5. **Zero Secrets in Code:** Zero passwords, API keys, or credentials are hardcoded or logged.
